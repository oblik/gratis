# Localization

## Content

An entry has one file for all locales. A localized field holds a map from locale to value; a shared field holds a plain value:

```json
{
  "heading": { "en": "Hello", "es": "Hola" },
  "photo": "/uploads/a1b2.jpg",
  "usps": [
    { "title": { "en": "Fast", "es": "Rápido" }, "icon": "bolt" }
  ]
}
```

- Whether a field is localized is declared in the schema. Text and markdown fields default to localized; image, link, boolean, select and reference to shared.
- A site with one locale stores plain values everywhere. Locale maps appear only once a second locale is configured.
- A missing locale falls back to the default locale at render time. The admin shows missing translations instead of blocking saves.
- The `site` single has the same shape, so navigation labels are localized the same way.
- Reordering a repeater reorders every translation at once, because the item is one object.
- The body of a Markdown entry is never localized (see [Schema](schema.md#storage)).

## Routing

The locale is a path prefix: `/about` and `/es/about`, both rendered from the `about` single. `routes.json` carries the i18n settings copied from the Astro config (locales, default locale, whether the default is prefixed) and, per page, the locales it exists in. The SPA builds output paths as locale prefix plus canonical path.

Gratis derives two facts from a page render and imposes nothing on the file layout:

- Locale: `Astro.currentLocale` when Astro's i18n is configured, otherwise a `lang` route param, otherwise the default locale.
- Template id: the route pattern with the locale segment removed, whether it is a literal like `es/` or a param like `[lang]/` or `[...lang]/`. `src/pages/es/about.astro`, `src/pages/[lang]/about.astro` and `src/pages/[...lang]/about.astro` all reduce to `/about`.

An existing localized site adds Gratis without moving a file. `locales()` gives the `lang` params for whatever pattern the site uses.

## Templates

Templates are locale-independent: `{{gratis:route:heading}}` carries no locale, and the renderer resolves it with the locale of the route it is rendering. `locale()` gives the current locale for `<html lang>` and similar.

## Recommended layout for new sites

`gratis init` scaffolds localized sites as `src/pages/[...lang]/about.astro`. A rest parameter may match zero segments, so `locales()` returns `undefined` for the default locale and `'es'` for Spanish, and one file builds both `/about` and `/es/about`:

```astro
export function getStaticPaths() {
  return locales().map(lang => ({ params: { lang } }));
}
```

Collection pages combine it with `getCollection` (see [Rendering](rendering.md#helpers)). Enabling i18n on an existing Gratis site means moving the pages one folder down.

Fallback, should Astro drop mid-path rest parameters: the documented layout with a three-line stub per page under `src/pages/[lang]/` that imports and renders the canonical page, generated by a `gratis` command.

## Deferred and out of scope

- Localized slugs (`/es/sobre-nosotros`): see [Roadmap](roadmap.md#localized-slugs).
- The admin's locale switcher and missing-translations view: after the MVP.
- Per-locale domains: out of scope.
